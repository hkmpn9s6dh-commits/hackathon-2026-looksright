给自主数据科学系统造一把尺子，专门量它会不会把「看着对、其实错」的结果交出去： 八个任务，每个埋一个真实世界里反复出现的坑；每个任务同时量两件事——实际做得怎么样， 以及它对自己成绩的估计准不准。

01 / 结果通用体检能捞回五类坑，剩下三类不行

A0 是标准 AutoML：全列进模型、随机 K 折、按库存指标挑最高分、把交叉验证当期望。A1 在它之上加七项 无差别的数据体检（重复行、哨兵值、伪 ID、评分时缺失的列、时序、类别不平衡、单特征近乎完全分开）。 A2 再加一个只有知道问题是什么才做得出的判断。

02 / 自知它报的数字，和它实际拿到的数字

横轴是实际，纵轴是自估。落在虚线上是老实，落在虚线上方是自信地错。24 次运行里，A0 最远的一次 报 0.98、实得 0.24（target_leak：把放款后才产生的催收字段当成了特征）；另一次报 0.34、 实得 −0.70（confounding：答错了题）。

03 / 八个坑都是可复算的

wine_dup　重复行

同一酒样被复检，重复行同时落进训练与验证。交叉验证被抬高，训练权重被那一小批酒带偏。

sentinel　哨兵值

缺测写成 999 / −999。模型读到「胆固醇 999」，而那 25% 其实是随机漏测的人。

target_leak　目标泄漏

催收次数、追回金额、首次还款天数——都是放款之后才有的字段。交叉验证 0.95，上线时这三列是空的。

temporal　时序

随机切分拿明天的数据预测今天；而且树不会外推趋势，真实未来一段只有一半的分数。

metric_mismatch　指标错配

按 AUC 选模型，决策却是「每天只能看 150 件」。AUC 0.84 看着能用，前 5% 只捞到三成缺陷。

confounding　混杂

医生把药开给重症，观察到的「用药组恢复好」是病情决定的。要答的是「谁会因为用药而受益」。

winner_curse　赢家诅咒

320 行上比 12 个候选，挑出来的那个的分数是挑出来的最高分，不是它的水平。

pseudo_id　伪 ID

导出表按结果排序后顺序编号，行号本身就是答案。新导出的 id 全在训练区间之外，树只能给同一个常数。

04 / 怎么用三条命令，一份可复算的结果

py -3 exp/run_all.py                          # 8 个任务 × 3 个参照系，写 results.json 与全部预测
py -3 verify.py                               # 127 项断言；两次完整运行 results.json 逐字节一致
py -3 evaluate.py --agent a1 --task wine_dup  # 单题评分

接一个外部系统：读 data/<任务>/train.csv 与 eval_features.csv， 交 predictions.csv（两列 row_id,value）与 claim.json （predicted_skill 与 flags）。评分脚本只认这两样，从不读你的代码。

05 / 边界不做什么

  • 不排名哪个系统最强。外部系统要按同一张任务卡提交才能比较。
  • 不训练大模型、不调外部 API。全部离线、单线程、固定种子。
  • 不宣称这些数字是可发表的绝对水平。技能分是相对各自任务明示的平凡基准算的。
  • 不假装八个坑穷尽了真实世界的坑。

已知弱点写在报告第六节：sentinel 一题对树模型几乎无伤（净损失 0.046 技能分）； metric_mismatch 一题 A2 的模型与 A0 统计上打平，优势全在自估；confounding 的双重稳健估计方差偏大； 八个任务都是合成数据。
