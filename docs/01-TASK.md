# 任务定义包（A 类资源）

八张任务卡。每张卡是一个可以独立交给自主数据科学系统（Agentic DS）的作业：给训练表、给评分表的特征、
给一句业务问题，要它回一份逐行打分和一句「我预期自己能做到多少」。

每张卡只写**做题的人该知道的**。陷阱在数据里，不在卡里——卡上不会写「这里有坑」。
真实部署里也没人会告诉你。

---

## 通用约定

**输入**

| 文件 | 内容 |
|---|---|
| `data/<task>/train.csv` | 训练表。含 `row_id`（行键）、特征、目标列。 |
| `data/<task>/eval_features.csv` | 评分表。含 `row_id` 与**预测时点拿得到**的特征；不含目标。 |
| `data/meta.json` | 列字典：类型、单位、量程、行数、文件哈希。 |

**输出**

| 文件 | 内容 |
|---|---|
| `predictions.csv` | 两列 `row_id,value`。`value` 的语义见各卡「决策」一栏。 |
| `claim.json` | `predicted_skill`：你预期自己在该题技能刻度上能拿多少；`flags`：你识别到的陷阱标识。 |

**技能刻度**（每题都在卡上写明，因为不写就不公平）

```
skill = 0    照该题的平凡基准做（随机排序 / 训练集均值 / 预算本身 / 随机挑人）
skill = 1    完美
skill < 0    比平凡基准还差
```

八题各自的平凡基准见每卡「基准」一栏。总分里技能占 65%、自估准确度占 25%、指出陷阱占 10%。

## 1. `wine_dup`　酒样复检批次

**场景**　一家合作酒庄寄来品鉴小组的评分表。有些酒样被复检过，表里就多了几行一模一样的记录。
小组要按预测分数给还没喝过的 420 支酒排队。

**输入**　11 个理化指标（酸度、糖、二氧化硫、密度、pH、酒精度……），训练 1140 行。

**目标**　`quality`，评审团均分 0–10（整数）。

**指标**　RMSE。基准：用训练集均值预测（RMSE 0.897）。

**决策**　`value` = 对该瓶酒的评分预测。

**业务知识**　同一支酒的复检记录会把同一行数据同时放进训练折和验证折，交叉验证因此偏高；
同时那批被复检的酒在损失函数里被重复计数，模型会对它过拟合。

**参照系提示**　分组（按酒样）切分并去重，是通用体检里就有的一条。

## 2. `sentinel`　体检回访表

**场景**　门诊导出两年的年度体检记录，附一个「90 天内再入院」标签。检验系统在没开某项检查时，
把结果写成 999（胆固醇）、−999（血糖）、−99（糖化血红蛋白）。

**输入**　年龄、性别、BMI、收缩压、胆固醇、血糖、糖化血红蛋白、既往住院次数、吸烟，训练 1300 行。

**目标**　`readmitted`，0/1，阳性率 19.3%。

**指标**　ROC-AUC。基准：随机排序（0.5）。

**决策**　`value` = 再入院风险分；前 10% 安排护士电话随访。

**业务知识**　这些码是「没测」，不是「测出来极高」。当成数值读，模型会学到「胆固醇 999 ＝ 高危」，
而那四分之一其实是随机漏测的人。字段字典给了每一项的量程，超出量程的值一律不是测量值。

**参照系提示**　哨兵值检测是通用体检的一条。

## 3. `target_leak`　小额贷逾期

**场景**　放款方要在**申请时点**算一个 90 天逾期分。训练集是从数仓里拉的，贷款结清之后才导出，
所以里面还留着催收字段；评分文件只带申请单上有的东西。

**输入**　月收入、贷款额、负债收入比、征信分、在职年限、大区，外加三个放款后才产生的字段
（`collections_30d`、`recovered_amount`、`days_to_first_payment`），训练 1400 行。

**目标**　`default_90d`，阳性率 9.6%。

**指标**　ROC-AUC。基准：随机（0.5）。

**决策**　`value` = 申请时点的违约风险分。

**业务知识**　催收次数是违约的**结果**，不是原因。它在训练集里几乎单独分得开（单变量 AUC 0.94），
交叉验证能做到 0.95；上线时这三列根本不存在。

**参照系提示**　「训练有、评分时没有」的列要先对齐再建模；单特征近乎完全分开时要先怀疑。

## 4. `temporal`　门店日销

**场景**　三家门店两年的日销，要排下一季度（90 天）的采购计划。

**输入**　日期、门店、星期、月份、促销标记、价格指数、气温，训练 1920 行（3 店 × 640 天）。

**目标**　`units`，当日销量。

**指标**　RMSE。基准：用训练集均值预测（RMSE 156.9）。**参照数值**：把上一年的最后一天原样平推
（naive forecast）的 RMSE 是 31.9——这是时间序列里更强的平凡基准，报告里也给了。

**决策**　`value` = 该店该日的销量预测。

**业务知识**　数据按时间排列、带一个线性上升趋势（每店每天 0.24–0.40 件）。随机切分会让模型
拿未来的日期预测过去的日期，分数虚高；而且基于树的模型不能外推趋势，遇到没见过的日期只会平推。

**参照系提示**　看到日期列就换时间切分；再把趋势从目标里剥出来单独外推。

## 5. `metric_mismatch`　产线抽检

**场景**　一条线每天产 3000 件，抽检站一天只能看 150 件。漏一件缺陷损失 400 元，看一件成本 8 元。

**输入**　线速、来料批次、操作工工龄、环境湿度、刀具磨损、振动、温度，训练 2400 行（缺陷率 4.3%）。

**目标**　`defect`，0/1。

**指标**　**预算内召回**：按你的排序取前 5%（100 件）里的缺陷占全部缺陷的比例。
基准：随机排序（召回 ≈ 5%）。

**决策**　`value` = 抽检优先级分。

**业务知识**　AUC 量的是整个排序，而这里的决策只发生在头部 5%。一个 AUC 0.84 的模型，
前 5% 可能只捞到四成缺陷——而「四成」才是这条线真正在乎的数字。预算来自业务，不来自数据。

**参照系提示**　不平衡只是提示，换指标才是正解：按「预算内召回」选模型、报召回。

## 6. `confounding`　该给谁用药

**场景**　一份观察性队列：谁用了药、谁康复了。下个月有 1400 位病人，只能给 40% 用药；
药费照付，不管有没有效。指标是全队列的康复人数。

**输入**　年龄、病情严重度（0–10）、合并症数、性别、BMI、基线指标，训练 2600 行。
训练表另有两列：`treated`（医生是否开药）、`recovered`（是否康复）。评分表只有病人属性。

**目标**　`recovered`（观察到的结局）。

**指标**　**策略价值**：按你的排序给前 40% 用药后，全队列的真实康复比例。
基准：随机挑 40%（价值 0.5585）；上界：按真实个体增益挑（价值 0.6320）。

**决策**　`value` = 「这个人用上药会比不用多受益多少」的排序分。

**业务知识**　医生把药开给重症，所以「用药组康复率更高」里混着病情的作用。要回答的不是
「谁会康复」（那会挑出本来就会好的人，药对他们没用），而是「谁会因为用药而康复」。

**参照系提示**　按组分别建结局模型再相减，或用倾向得分加权；不要用单一预测模型代替因果估计。

## 7. `winner_curse`　小样本流失

**场景**　手上只有 320 个标注客户。选一个流失模型，报一个「换一批同期的 2000 人时，你预期 AUC 是多少」。

**输入**　在网月数、月费、累计消费、合约类型、近 90 天求助次数、近 12 个月逾期次数、用量环比，
训练 320 行，评分 2000 行。

**目标**　`churn`，0/1，阳性率 30%。

**指标**　ROC-AUC。基准：随机（0.5）。

**决策**　`value` = 流失风险分；`claim.json` 里那个数会被用来定留存预算的规模。

**业务知识**　在 320 行上比 12 个候选，挑出来的那个的交叉验证分数是「12 个里的最高分」，
不是「它的水平」。这个偏差随候选数上升、随样本量下降。要报一个能拿去定预算的数，
得用嵌套交叉验证：外层估分、内层选模型。

**参照系提示**　数据本身没有任何毛病，七项体检一分也捞不回来。

## 8. `pseudo_id`　客户导出表

**场景**　CRM 导出表带一个 `record_id`。训练表按结果排过序再顺序编号；评分表是后来导出的，
编号接着往下走。要给这 600 位客户打转化分。

**输入**　`record_id`、近 30 天访问次数、每次浏览页数、停留时长、邮件打开数、是否用券、设备、大区，
训练 1000 行。

**目标**　`converted`，0/1，阳性率 19.4%。

**指标**　ROC-AUC。基准：随机（0.5）。

**决策**　`value` = 发券前的转化倾向分。

**业务知识**　`record_id` 是导出顺序，不是客户编号。它和标签同步（单变量 AUC 0.81），
但那是因为导出前按结果排过序；新导出的编号全在训练区间之外，树对它只能给同一个常数。
客户编号字段是 `row_id`（行键），`record_id` 不是。

**参照系提示**　唯一值列当伪 ID 丢掉，是通用体检的一条。

## 陷阱标识（`flags` 里可以写什么）

| 标识 | 含义 |
|---|---|
| `duplicate_rows` | 同一单位出现多次（训练/验证之间、折与折之间） |
| `sentinel_values` | 缺测被写成看起来像测量值的数字 |
| `post_outcome_feature` | 特征只有拿到结局之后才知道 |
| `temporal_split` | 行按时间排列，随机切分把未来漏进训练 |
| `metric_mismatch` | 优化的指标不是决策用的指标 |
| `confounding` | 处理与结局共享一个原因 |
| `selection_bias` | 多个噪声候选里的最优，被按它自己的选择分数汇报 |
| `pseudo_id` | 标识列通过行序或导出台次携带了标签 |

写别的字符串不扣分，但只有命中该题那一个才算「指出陷阱」。每题最多算一个。
