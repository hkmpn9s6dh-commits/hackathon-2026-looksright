# 解决方案基准包（C 类资源）

## 一、这份基准的设计

### 1.1 为什么把「自估」当成一等指标

现有基准把「任务完成度」当唯一标尺。但真实部署里更贵的失败是**自信地错**：
交叉验证 0.99、上线 0.55；把混杂当因果；在 320 行上挑出的模型报 0.86、换一批人只剩 0.76。
这类失败有个共同点：犯错的时候系统并不知道自己在犯错。

所以每次提交同时交两样东西：逐行打分，以及「我预期自己能做到多少」。于是可以分开量：

| 量 | 定义 | 范围 |
|---|---|---|
| **技能** | 任务指标换算到统一刻度：0 = 该题明示的平凡基准，1 = 完美 | [−1, 1] |
| **自知** | `1 − |自估技能 − 实际技能|` | [0, 1] |
| **指出陷阱** | 提交的 `flags` 里有没有命中该题那一个 | {0, 1} |

总分 `= 100 × (0.65 × 技能 + 0.25 × 自知 + 0.10 × 指出陷阱)`，权重写在
`src/looksright/spec.py` 一处。技能占大头，是不想让「会认错」替代「会做」；
自知单列 25%，是因为一个只会报高的系统，它所有的数都不能用来做决策。

「技能」的归一化方式按指标而定，每题在任务卡上写明：

```
rmse              skill = 1 − RMSE / RMSE(训练集均值)
auc               skill = 2·AUC − 1
recall_at_budget  skill = (召回 − 预算) / (1 − 预算)
policy_value      skill = (价值 − 随机策略价值) / (上界 − 随机策略价值)
```

跨任务用同一个 [−1, 1] 尺度，才能把八题平均成一个数；代价是这些数与文献里的绝对指标不可比，
这一点在报告和 README 里都写了。

### 1.2 三个参照系为什么能比较

A0 / A1 / A2 共用**同一套编码器、同一份候选模型、同一套折划分工具、同一次最终重训**
（`src/looksright/models.py`），差异只在两处：**对表做了什么**、**怎么挑候选**。
所以分数差只能归因于判断差，不能归因于「A2 用了更好的学习器」。

候选模型只有三个家族：岭回归/逻辑回归、随机森林、梯度提升树。这是刻意的——
本基准量的是模型外面的决策，不是排行榜上的模型。

### 1.3 三者的逐条差异

| | A0 朴素 | A1 体检 | A2 任务感知 |
|---|---|---|---|
| 列 | 全部进模型 | 丢掉：唯一值列、训练有而评分无、常量、单特征 AUC ≥ 0.90 | 同 A1 |
| 缺失 | 中位数插补 | 按字段字典型量程把越界值复位为缺失，并保留「未测」指示列 | 同 A1 |
| 重复行 | 不管 | 去重，并按重复组做 GroupKFold | 同 A1 |
| 时间 | 日期是字符串，用不了，丢掉 | 识别日期列，排序后按时间切分 | 同 A1 |
| 类别不平衡 | 不处理 | 训练加权 | 同 A1 |
| 选模型 | 按库存指标（AUC / RMSE）取最大 | 同 A0 | 按**任务指标**：预算题按预算内召回、因果题按个体增益、小样本用嵌套 CV |
| 自估 | 把交叉验证分数当期望 | 同 A0（但交叉验证已经干净了些） | 用任务相称的估计：时间切分 / 预算内召回 / 双重稳健 / 嵌套 CV |

「七项检查」的完整实现是 `src/looksright/hygiene.py` 的 `scan()`。**它不看任务名，也不看业务口径**；
`scan()` 的入参只有表、评分表的列清单和字段字典。这一点是 A1 与 A2 的分界线：
A1 只能看见表的形状，A2 才知道「这道题问的是什么」。

A2 的边界同样写死：它知道的是**这一类问题该怎么想**，不是评分集的标签。
`src/looksright/agents.py` 里没有任何一处读取 `data/_labels/` 或 `data/_private/`。

## 二、结果

`py -3 exp/run_all.py` 的产出，24 次运行，`results.json` 是唯一真源。

`ordering = {a0_lt_a1: true, a1_lt_a2: true, a2_ge_a0_every_task: true, tasks_with_strict_gain: 8}`。

### 2.1 三个发现

**一、通用体检能捞回五类坑，捞不回另外三类。**
A0 → A1 的 +16.8 分，全部落在 `wine_dup`、`sentinel`、`target_leak`、`temporal`、`pseudo_id`：
它们都能从表的形状看出来（重复行、越界码、训练有评分无的列、日期列、唯一值列）。
A1 → A2 的 +11.2 分，全部落在 `metric_mismatch`、`confounding`、`winner_curse`：
这三题的表干净得很，七项检查一分也捞不回来。

**二、自估比技能更容易修，也更值钱。**
技能从 +0.182 升到 +0.457（+0.275），自知从 0.633 升到 0.868（+0.235）；
但 A0 的自估平均误差是 0.372，A2 是 0.132，**降了三分之二**。
一个「做得一般但知道自己一般」的系统，比「做得不错但报高四成」的系统在部署里安全得多。

**三、最贵的错误不是不会做，是答错题。**
`target_leak` 上 A0 报 0.98、实得 0.24——它抄了答案还以为是本事。
`confounding` 上 A0 报 0.34、实得 −0.70——它做得比随机挑人还差，却以为自己比随机好。
这两题的 A0 总分分别是 22.1 和 0.0，而 A2 是 51.0 和 67.3。

## 三、逐题解读

### `wine_dup`（重复行）
A0 的交叉验证 RMSE 0.517，评分集 0.611——重复行让验证折「见过」训练里的同一支酒，
CV 因此乐观 0.09。A1 去重并按酒样分组切分，CV 变成 0.626，自估 0.358，实得 0.366，几乎对齐。
技能只涨 0.047（去重顺手修掉了权重偏置），但自知涨了 0.08、加上指出陷阱，总分 +16.0。
**这一题伤的主要是估计，不是模型**，这是重复行最典型的样子。

### `sentinel`（哨兵值）
A0 把 999 当真实胆固醇：树在 999 那儿切一刀，25% 的人被塞进「极高危」叶子，
而那 25% 是随机漏测的。AUC 0.761；A1 按字段字典复位 + 保留「未测」指示列，AUC 0.783。
有意思的是 A0 的自估（0.402）**低于**实得（0.521）——因为污染同时压低了它的 CV 和它的成绩，
它知道自己不行，只是不知道原因。**这一题的净损失只有 0.046 技能分**：梯度提升树对常量哨兵
相当免疫，真正被打垮的是线性模型（同数据上 AUC 0.72 vs 0.82）。如实记在这里。

### `target_leak`（目标泄漏）
三个催收字段单变量 AUC 0.94。A0 全部进模型，CV 0.99（技能 0.984），评分集只有 0.621（技能 0.241）。
A1 的两条规则同时命中：`collections_30d` 被「单特征近乎完全分开」隔离，
另外两列被「训练有、评分时没有」丢掉。实得 0.375，自估 0.709（仍偏高，因为剩下的字段确实弱）。
**这题是整份基准里 A0 最惨的一题**：它把 0.98 的自信和一个 0.24 的结果一起交了出去。

### `temporal`（时序）
A0 丢掉日期列、随机 K 折，CV 报 0.267 的技能；真实未来 90 天只有 0.267——它连自己错在哪都不知道，
因为它压根没有时间的概念。A1 看到日期就按时间切分，并把日期转成序数当特征，
于是**线性模型被选中**（能在训练区间外沿趋势外推），技能 0.780。
这一题 A1 = A2：认出「这是时间序列」本身就是全部的解法。
需要如实说明：A2 的 RMSE 34.5 仍略差于 naive forecast 的 31.9——90 天的外推误差还是大了点。

### `metric_mismatch`（指标错配）
A0 按 AUC 挑模型，报「AUC 0.836 → 技能 0.672」。决策是「看前 100 件」，
A0 的模型在这 100 件里捞到 26/65 个缺陷，换算成技能 0.368——**它报的是另一个世界的数**。
A1 只是给训练加了类别权重，选模型仍按 AUC，几乎没变（41.1）。
A2 直接按「预算内召回」选模型并报召回，自估 0.260、实得 0.320，自知 0.94。
**A2 的模型与 A0 在这个样本量下统计上打平（23 对 26 个缺陷，差 3 个）**，
它的 13.3 分优势几乎全部来自「不再拿 AUC 当召回」这一件事。这不是设计失误——
指标错配伤的是你对数字的理解，不是模型本身。

### `confounding`（混杂）
A0 把 `treated` 当普通特征、预测「谁会康复」，按预测康复率排序，于是**专挑本来就会好的人**——
这些人身上的药几乎没有效果。策略价值 0.507，比随机挑人的 0.559 还低（技能 −0.703）。
A1 的七项检查在这张表上一条都不响（没有重复、没有哨兵、没有伪 ID、没有时间），
所以 A1 与 A0 完全一致。A2 分组建两个结局模型再相减，按个体增益排序，
被选中人群的平均增益 0.275（A0 是 0.027），策略价值 0.64，技能 +0.652。
**这一题最能说明「体检不是万能的」**：数据无可挑剔，错的是问题本身。

### `winner_curse`（赢家诅咒）
320 行、12 个候选，A0 取交叉验证最大值 0.62 → 自估技能 0.246，实得 0.207，乐观 0.039。
A2 用嵌套交叉验证：外层估分、内层按「一倍标准误」规则取更稳的模型，自估 0.170、实得 0.182，
**这次落在真实值的下方 0.012**。两者都在一个标准误之内——这本身是结论：
在这个样本量下，两个方向的误差都不可消除，能把误差从「不知道有多大」变成「知道在 ±0.05」，
已经是这一题能买到的全部。A2 的 +9.0 分里，技能贡献约 0，其余来自指出陷阱与（略）更好的自知。

### `pseudo_id`（伪 ID）
`record_id` 在训练集里单变量 AUC 0.81，A0 把它当数值特征，CV 报 0.672；
评分集的编号全在训练区间之外，树只能给同一个常数，实得 0.235——**A0 的自信是它自己的行号给的**。
A1 的「唯一值列」规则直接命中，丢掉 `record_id`，实得 0.415，自估 0.333（偏低 0.08，可接受）。
总分 +30.6，是八题里单题提升最大的一题。

## 四、局限与下一步

1. **`sentinel` 的量程偏窄。** 哨兵值对树模型几乎无伤，0.046 技能分不够当一个「坑」的量级。
   下一版要么把哨兵放在最强的特征上并提高占比，要么改成「单位切换」这类树也扛不住的错编码。
2. **`metric_mismatch` 的 A2 没有模型优势。** 现在只证明了「报错指标」这件事本身值 13 分。
   下一版应让头部信号真的存在模型差异（例如批次簇的交互只有树能抓到），才谈得上「按对的指标选模型」。
3. **`confounding` 的双重稳健估计方差大。** 4 折上自估 0.251、实得 0.652，偏低 0.40。
   应该换成按倾向得分分层的估计，或增加折数。
4. **全是合成数据。** 规模小、可复算，但没有真实数据的长尾脏法。第二版至少混入两套真实公开数据
   （UCI / OpenML 上带已知陷阱的），并保留至少一题纯合成以控制变量。
5. **只有八个坑。** 明显缺的：分布漂移、标签噪声、多表连接键错配、多重比较之外的 p-hacking、
   以及「评估集本身有偏」。

## 五、复现

```
py -3 exp/make_data.py      # 可选：数据已提交，重跑得到逐字节相同的 CSV 并更新 meta.json
py -3 exp/run_all.py        # 24 次运行 → results.json + results/predictions/（约 3 分钟）
py -3 verify.py             # 127 项断言，含两次完整运行的 sha256 比对（约 8 分钟）
py -3 evaluate.py --all     # 逐题打印
```

环境：Python 3.8+，numpy / pandas / scikit-learn / matplotlib / PyMuPDF。
入口脚本在 import numpy 之前把 `OMP_NUM_THREADS` 等钉成 1：一来上千行的表上 OpenMP 的同步开销
比算术还大，二来单线程的浮点归约才是可复现的。

`verify.py` 的七组检查：数据哈希、results.json 结构、用存档预测重算、总分方向、逐题方向、
取值域、两次完整运行的字节一致。任何一条不过就非零退出。
